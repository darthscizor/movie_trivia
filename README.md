#### Description:
I made a simple movie trivia quiz web application in my own VSCode environment.  It was created using a combination of python, SQLite3, javascript, and Jinja that I learned over the course of taking CS50.  My main inspiration for creating this project was to make a movie trivia app that my dad, who is an avid movie lover, could enjoy.  As such, I wanted to make the questions a little more difficult than other trivia quizzes I had seen out there.  It's a simple 10 question multiple choice quiz that comes from a larger database of questions.  So the content and the order of the questions in each quiz is different every time.  After opening the app, the user is instructed to register an account unless they already have one in which case they can just login then start a quiz.  Then they can access their account info from the main menu which displays their username and high score on the quiz.  Afte clicking the start quiz button below they will be presented with their first question.  If they get the question correct their chosen answer button will turn green.  If they get it incorrect then their chosen answer will turn red and the corret answer will turn green.  The user can then either click the next question button and at any point choose to exit the quiz by clicking the exit quiz button.  After completing the quiz the user is presented with a results screen showing their score and links back to the main menu.

Initally, I struggled a lot setting up my own vs code environment because up until now CS50 has provided us with it's own built in environment.  Generally speaking, that was probably my biggest learning curve when it came to this project.  Probably as a result of this, there were a lot of smaller things throughout my project that were different from say the finance or homepage problem sets.  For instance when finishing then exiting a quiz I had to learn/relearn how data flows within a given session.  This was more specifically my biggest hurdle that I had to overcome.  Because I wanted to save user data while also clearing the session so the same or different could use the quiz next and not have scores or other data overlap.  Through this I also learned how easily said data can become corrupted when accessed directly through a method such as browser history.  When putting the quiz itself together, my first big choice was whether to have multiple choice or fill in the blank questions.  I ultimately decided on multiple choice because I felt it was more user friendly and less disheartening in the case of a user who doesn't know the answer.  My next biggest hurdle to overcome was making sure the user's score stayed consistent throughout the quiz and wasn't subject to user activity such as going back or forward on the currently displayed page, closing the page entirely, or accessing the page directly from their browser history.  Initially I wanted to have a layout on each question page akin to something like the tv show Who Wants to be a Millionaire but I ultimately decided to format the pages the way I did because it made the most sense for questions and answers of varying lengths.  It was also frankly easier to code.  The colors for everything were chosen at random but I think that worked out in the end as well.  I used DB Browser for SQLite as my method of creating then importing my database to VS Code.  This database included the trivia questions themselves, the choices that each question has, a scores table to calculate and display the scores from each game session, and lastly a users table that contains usernames, hashs for passwords, and user high scores.

Overall I am happy with the way things turned out but this is definitely a concept I would like to expand further on later on down the line.  In future iterations I would like to add a fill in the blank version of the quiz as well as difficulty settings for both types of quizzes.  I wanted to keep the content strictly related to movies but I could also see myself making a broader trivia application in the future.  I'm also very interested in making video games either as a hobby or a future career so making a simple web application like this seemed like a good first step in that direction.
